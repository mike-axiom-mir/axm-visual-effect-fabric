# Cellular nearest-feature 2D field

## Capability

`fx.field.cellular-nearest2d` adds one reusable deterministic scalar-field donor for cellular / nearest-feature structure without replacing the existing fBm donor.

The retained source is `axm.cellular-field-source/v0.1`. It stores only source meaning required to reproduce the continuous field: id, algorithm version, seed, frequency, jitter, offset, distance-vs-inverse-distance mapping, and the fixed bounded neighbor-search radius. Grid resolution is not canonical source truth.

The derived `axm.scalar-field-grid/v0.1` working set intentionally uses the same generic scalar-grid shape as the existing fBm donor. That keeps older grid sampling useful while avoiding any claim that the fBm continuous-source sampler understands the new cellular source.

## Truth boundary

- `normalizeCellularFieldRequestHand` creates and hashes retained cellular source truth.
- `buildCellularFieldGridHand` revalidates that source hash and the fixed algorithm/search contract before sampling.
- Width, height and `maxCells` are rebuild controls only. Rebuilding at another resolution must not rewrite the retained source.
- The grid is marked `derived: true` and `rebuildable: true`; its hash binds source hash, resolution and sampled values.
- Human, AI and deterministic-program callers use the same Hands. Caller kind is not part of field generation.
- No renderer is authoritative over this source. This bounded improvement intentionally stops at reusable scalar source + derived grid rather than choosing a visual style or consumer meaning.

## Deterministic sampling

Each integer cell owns one feature point. Two repository-local 32-bit mixes derive the point coordinates from `(seed, cellX, cellY)`. `jitter=0` places features at cell centers; `jitter=1` allows the full cell area. A normalized probe checks the fixed 5x5 neighborhood around its containing cell and returns the nearest Euclidean feature distance, normalized into `[0,1]`. `inverse-distance` only flips that retained value mapping.

The implementation is independently authored in this repository. No external Worley/cellular-noise source, shader, library, texture, asset or renderer implementation was copied or imported. The name “cellular” describes the procedural family; this is not a claim of byte/code compatibility with a third-party implementation.

## Structural budgets and performance honesty

Default derived grid: `48 x 32 = 1,536` cells.

Hard grid ceiling: `16,384` cells, with each axis bounded to `4..128`.

The fixed nearest-feature search checks `25` feature points per scalar sample, so the default grid performs `38,400` feature-distance probes and the hard grid ceiling implies at most `409,600` such probes per rebuild.

Those are structural operation counts only. FPS, CPU/GPU time, memory residency, browser cost, battery, thermals and device scalability are **NOT_TESTED**.

## Evidence boundary

The targeted proof covers deterministic caller neutrality, source preservation across grid resolutions, compatibility with the existing generic scalar-grid sampler, predictable zero-jitter geometry, distinct seeded/jittered fields, source-lineage drift rejection, rejection of self-consistent unsupported algorithm state, bounded inputs and hard budget failures.

No browser/device pixels are generated by this donor, so visual attractiveness, readability, compositing quality, anti-aliasing and aesthetic suitability are **NOT_TESTED**. A later renderer or consumer may inspect/use this field without gaining authority to rewrite the retained source.

## Consumer boundary

The field is consumer-neutral. It contains no game, terrain, material, UI, world, weather, product or Universal Creation meaning. Existing consumers that operate on `axm.scalar-field-grid/v0.1` can use the derived grid contract where appropriate. Existing continuous fBm-only consumers should not silently reinterpret `axm.cellular-field-source/v0.1`; a future generic continuous-scalar sampling adapter should be added only when a concrete reusable consumer requires it.

## Next bounded target

Prefer one evidence-driven composition that consumes this new field without rewriting it—for example a coverage-mask or contour adapter that explicitly accepts multiple continuous scalar-source families. Do not mass-port the donor into Universal Creation or product/game repositories before a real consumer asks for it.
